화면을 따라가며 확인하기

실제로 열린 화면만 기록합니다. 각 화면을 누르면 정의로 이동합니다.

처음 가입하고 들어오기

신규 이메일 가입의 앱 내 화면 순서입니다. 소셜 가입은 이메일 인증·비밀번호 단계를 건너뜁니다.

  1. 앱 실행 · 시작 화면
  2. 로그인 · 시작
  3. 로그인 · 이메일 입력
  4. 회원가입 · 약관 동의
  5. 회원가입 · 이메일 인증
  6. 회원가입 · 비밀번호 설정
  7. 회원가입 · ID 입력
  8. 회원가입 · 이름 입력

가입 성공은 액션입니다. 이후 권한·튜토리얼 표시 조건에 따라 첫 이용 화면으로 이어집니다. 가입 후 로그인 화면을 다시 필수로 거치지 않습니다.

가입 후 첫 이용

AOS 신규 가입의 대표 경로입니다. iOS는 튜토리얼·권한 조건에 따라 순서와 표시 여부가 다릅니다.

  1. 첫 이용 · 권한 안내
  2. 첫 이용 · 서비스 안내
  3. 첫 이용 · 환영 영상
  4. 디스커버리 · 발견

안내 건너뛰기·기존 동의·보존된 딥링크가 있으면 실제로 표시된 화면만 기록합니다. 디스커버리 도착을 무조건 가정하지 않습니다.

다시 로그인하고 탐색하기

로그인이 풀린 기존 이메일 회원의 경로입니다. 로그인 상태가 유지되면 인증 화면을 생략합니다.

  1. 앱 실행 · 시작 화면
  2. 로그인 · 시작
  3. 로그인 · 이메일 입력
  4. 로그인 · 비밀번호 입력
  5. 로그인 · 2단계 인증조건부 화면
  6. 디스커버리 · 발견

2단계 인증은 필요한 회원에게만 표시합니다. 로그인 성공은 별도 화면이 아닙니다.

작업물을 발견하고 사람에게 연결하기

발견과 검색에서 같은 상세 화면으로 이어집니다. 진입 경로가 달라도 상세 화면 이름은 유지합니다.

  1. 디스커버리 · 발견
  2. 포트폴리오 · 상세
  3. 크리에이터 · 프로필
  4. 크리에이터 · 포트폴리오
  5. 대화 시작 · 목적 선택조건부 화면
  6. 채티 · 1:1 대화

노크 화면은 플랫폼·관계 상태에 따라 목적 선택 또는 메시지 입력입니다. 이미 대화 중이면 대화방으로 바로 이동할 수 있습니다.

파인더에서 크리에이터 찾기

검색→결과→조건 조정→프로필 순서로 실제 보이는 목적지를 기록합니다.

  1. 파인더 · 검색
  2. 파인더 · 크리에이터 검색 결과
  3. 파인더 · 크리에이터 필터
  4. 파인더 · 크리에이터 검색 결과
  5. 크리에이터 · 프로필

필터 값을 바꾸는 행위는 화면이 아닙니다. 필터 화면을 열고 결과로 돌아오는 방문을 구분합니다.

내 프로필을 등록하고 수정하기

마이에서 자기표현을 준비합니다. 아래 화면들은 필요한 등록 항목을 선택할 때 열리며 모든 회원의 필수 순서는 아닙니다.

  1. 마이 · 프로필
  2. 프로필 등록 · 커버 스타일 선택
  3. 프로필 등록 · 커버 정보 입력
  4. 마이 · 프로필
  5. 프로필 등록 · 자기소개 입력
  6. 커리어 · 이력 관리
  7. 커리어 · 경력 입력
  8. 마이 · 프로필

커버·자기소개 폼 안 입력 필드는 같은 화면입니다. 등록 이력에 따라 첫 마이 대신 커버 선택이 먼저 보일 수 있습니다.

포트폴리오를 올리고 확인하기

작업물 등록부터 첨부 편집, 내 목록에서 결과 확인까지의 대표 경로입니다.

  1. 마이 · 포트폴리오
  2. 작업물 등록 · 종류 선택조건부 화면
  3. 포트폴리오 · 작성
  4. 첨부 · 이미지 자르기조건부 화면
  5. 포트폴리오 · 작성
  6. 마이 · 포트폴리오
  7. 포트폴리오 · 상세

종류 선택·이미지 편집은 실제 열린 경우만 기록합니다. 저장 후 도착지는 실제 앱 이동을 따르며 완료 액션을 가상의 화면으로 만들지 않습니다.

프로젝트에 참여해 협업하기

프로젝트를 발견하고 신청한 뒤 대화로 이어지는 흐름입니다.

  1. 파인더 · 프로젝트 검색 결과
  2. 프로젝트 · 상세
  3. 프로젝트 · 참여 신청조건부 화면
  4. 채티 · 프로젝트 대화 목록
  5. 채티 · 프로젝트 대화

지원 수락과 대화방 진입은 관계·권한에 따라 달라집니다. 이 경로는 가능한 여정이며 즉시 자동 이동을 뜻하지 않습니다.

팀을 만들고 함께 작업하기

팀 정보 등록과 멤버 초대, 팀 작업물·대화로 이어집니다.

  1. 팀 · 내 팀과 초대
  2. 팀 · 정보 입력
  3. 팀 · 포트폴리오
  4. 팀 · 멤버
  5. 팀 · 멤버 초대조건부 화면
  6. 채티 · 팀 대화

팀 정보 편집과 초대는 권한이 있을 때만 가능합니다. 같은 팀 프로필의 호스트와 선택 탭을 동시에 기록하지 않습니다.

각 행의 ‘GA 화면 제목’은 그대로 수집할 고정값입니다. ‘개발 키’는 구현과 목록 관리를 위한 영문 식별값입니다. 한국어 제목을 GA 표시값으로 사용하는 안을 기본으로 작성했으며, 표시 언어는 팀 적용 전에 확정합니다.

무엇을 한 화면으로 정하는가

사용자가 전면에서 읽거나 입력하는 목적지가 한 화면입니다. 전체 페이지뿐 아니라 목록이 바뀌는 탭과 독립적인 선택·입력 과업을 수행하는 시트도 포함합니다. 같은 목적지의 로딩·빈 결과·오류 문구·입력 칸·키보드·버튼 클릭은 별도 화면이 아닙니다.

마이와 타인 프로필은 소유자와 가능한 과업이 달라 구분합니다. 반면 같은 포트폴리오 상세에 디스커버리·파인더·프로필 중 어디서 들어왔는지는 진입 속성으로 구분하고 화면 이름은 유지합니다. 화면에 보이는 회원명·검색어·콘텐츠 제목·고유번호는 화면 제목에 붙이지 않습니다.

적용 범위

기준은 2026년 9월 9일 고정한 AOS 3.1.0·iOS 3.0.2·Front Web의 알파 후보 소스입니다. 화면 제목은 이번 정의이며 현재 이미 이 이름으로 수집된다는 뜻이 아닙니다. 실제 알파 배포와 설치본의 일치, GA 수신 확인은 남아 있습니다.

이전 화면 분석 목록은 근거 자료로 사용했습니다. 레거시·조건부 진입과 화면이 아닌 항목은 본문 화면 정의에서 분리했습니다. 특정 화면의 플랫폼 표시는 소스 근거가 있는 구현 환경이며 모든 사용자에게 해당 화면이 노출된다는 뜻은 아닙니다.

화면 경계를 정한 이유

가입 완료와 로그인 성공

현재 확인한 가입 흐름에서는 이름 입력 화면의 ‘회원가입 완료’ 버튼 뒤에 가입 성공 처리가 일어납니다. 독립된 가입 완료 페이지를 새로 가정하지 않습니다. 따라서 화면명은 ‘회원가입 · 이름 입력’이고 가입 성공은 별도 sign_up 이벤트입니다. 이후 실제로 나타나는 권한 안내·이용 안내·환영 영상·메인에 각각 해당 화면 이름을 사용합니다.

가입 뒤 다시 로그인 화면을 반드시 거친다는 순서를 만들지 않습니다. 가입 성공 시 인증 상태가 저장되므로, 신규 가입 경로와 기존 회원 로그인 경로는 서로 다른 흐름입니다. 딥링크나 기존 동의 상태에 따라 첫 목적지가 바뀔 수 있습니다.

마이와 타인 프로필

‘마이 · 프로필’은 내 커버·이력 중심의 화면, ‘크리에이터 · 프로필’은 다른 사람의 같은 화면입니다. 소개와 작업물 탭은 실제 전면 상태에 따라 별도 이름을 사용합니다. 프로필 상단 헤더와 하단 목록이 함께 보인다고 두 화면을 동시에 보내지 않습니다.

타인의 프로필 정보를 수정하는 기능은 확인한 소스에서 근거를 확보하지 못했습니다. 타인 흐름에는 프로필 열람·리스펙트·인맥·노크·대화를 정의했고, 프로필 정보 수정은 내 정보 또는 관리 권한이 있는 팀 정보에만 배치했습니다.

프로필 등록 폼의 내부 단계

커버 정보 입력 폼은 직업·ID·이름·한 줄 소개·표지·프로필 사진을 한 스크롤 편집 흐름으로 보여 줍니다. 자기소개 폼도 키워드·이미지·소개 글을 같은 화면 안에서 펼칩니다. 각각 하나의 화면명으로 기록하고 어느 입력 단계인지는 속성으로 구분합니다.

다만 폼에서 직업 검색·이미지 자르기 같은 독립 화면을 열면 새 화면입니다. Web의 커버 스타일 선택 페이지 역시 네이티브 입력 폼과 분리되어 있어 다른 이름을 부여했습니다.

소통과 협업

채티의 대화·라운지·프로젝트 목록은 전면 내용이 바뀌는 탭이므로 각각 정의합니다. 1:1·라운지·프로젝트·팀 대화방은 이용 목적과 관리 구조가 달라 분리합니다. 같은 방 안 메시지 전송·읽음·첨부 버튼 클릭은 별도 화면이 아닙니다.

프로젝트 콘텐츠 상세, 프로젝트 참여 신청, 지원자 목록, 프로젝트 대화방은 같은 기능 묶음에 속해도 서로 다른 화면입니다. 반대로 팀 정보 입력의 신규·수정은 같은 폼의 모드이므로 한 화면 이름을 유지합니다.

개발 적용 규칙

화면 정의 목록의 고정 제목을 전송합니다. 클래스명이나 기능명으로 화면 제목을 다시 만들지 않습니다. 기본 키·제목·버전은 한 사전으로 관리하고 iOS·AOS·Web이 같은 사전을 사용합니다.

화면 이름을 정하는 순서

  1. 앱 실행 후 실제 전면 목적지를 확인합니다. 비로그인 시작, 튜토리얼, 메인, 딥링크 중 실제 나타난 화면을 고릅니다.
  2. 목적지가 프로필이면 내 프로필인지 타인 프로필인지 구분합니다.
  3. 탭이 있는 화면이면 현재 선택된 탭이 제목을 소유합니다. 부모 호스트의 조회를 함께 보내지 않습니다.
  4. 독립 과업 시트가 전면에 열리면 그 시트 이름으로 전환합니다. 단순 확인 팝업·키보드는 현재 화면 이름을 유지합니다.
  5. 새로운 목적지가 실제로 표시된 시점에 한 번 전송합니다. 프리로드·재렌더·같은 탭 재선택에는 보내지 않습니다.
