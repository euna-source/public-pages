# QA와 수집 완료 기준

QA는 테스트 동작 한 번이 어떤 이름·값·건수로 남아야 하는지를 먼저 정하고 실행합니다. 기기 로그에 함수 호출이 보이는 것, GA에 이벤트가 도착하는 것, 내부 분석에서 조회되는 것은 각각 다른 확인 단계입니다.

테스트 전 실제 알파 앱 버전·빌드, Web 배포 식별값, 테스트 계정 조건, GA 속성·스트림, 내부 수신 환경, 수집 동의 상태를 기록합니다. 테스트 이벤트에는 식별 가능한 테스트 실행값을 붙이고 운영 데이터와 분리합니다. GA 디버그 수신과 내부 적재의 관찰 시간을 먼저 정하며, 그 시간이 지나기 전에는 누락으로 단정하지 않습니다.

| 케이스 | 동작 | 새 계약의 기대 결과 |
|---|---|---|
| QA-01 | 홈에서 팀 목록 진입 | 각 플랫폼 team_list 1회. contacts_team과 중복 가산 없음 |
| QA-02 | 제안 상세에서 첨부 미디어 열기 | proposal_detail 1회 뒤 media_viewer 1회 |
| QA-03 | 0.1초 간격으로 서로 다른 프로필 A→B 이동 | profile_home 2회, 방문 식별값 2개. 이름이 같아도 대상 전환을 누락하지 않음 |
| QA-04 | 같은 방문에 마운트·가시성 콜백 반복 | screen_view 1회. 동일 이벤트 재전송은 같은 event_id |
| QA-05 | 현재 프로필과 양옆 프로필을 사전 로딩 | 보이는 현재 프로필만 1회. 옆 프로필이 실제 보일 때만 추가 1회 |
| QA-06 | 검색에서 크리에이터→포트폴리오→프로젝트 탭 이동 | 각 finder_result_* 1회. finder_result 부모를 함께 세지 않음 |
| QA-07 | 일촌→팔로워→팔로잉 이동 | contact_first·contact_follower·contact_following 각각 1회. 일촌 요청 목록의 동시 노출을 별도 화면으로 세지 않음 |
| QA-08 | 북마크 두 탭 이동 | activity_bookmark_creator·activity_bookmark_portfolio 각각 1회. 부모 제외 |
| QA-09 | 채티의 개인·라운지·프로젝트 목록 이동 | 선택된 chat_list_*만 기록. chat_home 중복 없음 |
| QA-10 | 같은 화면에서 앱·브라우저를 숨겼다 복귀 | 방문 수 유지. screen_suspend·screen_resume과 전면 체류 구간만 추가 |
| QA-11 | 상세로 이동한 뒤 뒤로 가기 | 재노출 목적지의 새 방문 1회, navigation_type=back |
| QA-12 | 웹뷰를 가리는 네이티브 화면을 열었다 닫기 | 가려진 동안 체류 중지. 실제 목적지 이동 여부에 따른 복귀 규칙 적용 |
| QA-13 | 딥링크가 로그인 후 목표 화면으로 복귀 | 실제 보인 로그인 단계와 최종 목적지만 기록. 중간 리다이렉트·사전 화면 제외 |
| QA-14 | 데이터 없음·부분 재조회 오류·독립 오류 화면 | 정상 빈 결과는 원래 이름과 empty. 재조회 알림은 방문 추가 없음. 독립 오류 표면은 system_error 또는 system_not_found |
| QA-15 | 작성 과정 세부 단계 이동 | 정의된 flow_step_view만 증가. 같은 작성 화면의 반복 렌더는 screen_view에 더하지 않음 |
| QA-16 | 노크·리스펙트의 전면 선택 과업 실행 | 해당 독립 과업 이름 1회. AOS 입력형 노크와 iOS 선택형 노크를 구분 |
| QA-17 | 홈 안 Web 모듈·갤러리 인트로/설명 전환 | 내장 모듈 노출·단계 이벤트만 증가. 부모 방문 수는 늘지 않음 |
| QA-18 | 모듈 로드 5분 후 진입해 전면에서 1분 사용 | 체류는 1분 구간. 사전 대기 5분 제외 |
| QA-19 | 네트워크 차단 후 재연결·재시도 | 발생시각과 event_id 유지. 내부 수신의 중복 행 없음. 보관 한도를 넘은 폐기는 진단 가능 |
| QA-20 | 앱 종료·프로세스 종료로 이탈 로그 유실 | 새 시작은 새 방문. 이전 체류를 임의로 연장하지 않고 종료 누락 상태로 표시 |
| QA-21 | 새 Web과 구버전 앱 조합 | 수집 프로토콜 지원 여부로 발신 경로 선택. 두 수집 경로를 동시에 보내지 않음. legacy 구분 가능 |
| QA-22 | 수집 비활성·동의 전후·로그아웃 | 해당 정책대로 수집·중단하고 이전 사용자의 식별 상태가 다음 사용자에게 섞이지 않음 |
| QA-23 | 프로젝트 검색 결과 체류 기록 | iOS·AOS에서 실제 지원 API 또는 새 공통 이벤트로 수신. 400 응답을 성공으로 처리하지 않음 |
| QA-24 | GA 자동 기록과 명시 기록을 함께 관찰 | 같은 실제 방문이 중복 집계되지 않도록 수집 설정·필터·발신 책임 확인 |
| QA-25 | OS 사진 선택기·공유 시트·내부 QA 열기 | 제품 화면 조회 증가 없음. 필요하면 별도 행동·진단 이벤트만 기록 |
| QA-26 | 과거 이름 표본과 새 정의 비교 | finder·proposal_detail·작성 완료 값이 문맥에 맞게 분리. 복원할 수 없는 값은 unknown |

전체 화면 목록의 적용 대상에는 기본 진입, 이탈 후 재진입, 빈 결과 또는 해당 접근 조건을 확인하는 케이스를 연결합니다. 표본 26개를 통과해도 전체 화면이 검증된 것은 아닙니다. 화면별 체크리스트는 [screen-qa-checklist.json](screen-qa-checklist.json)에 준비했으며 모든 결과는 미실행 상태입니다.

| 완료 단계 | 필수 증거 | 현재 상태 |
|---|---|---|
| 조사 기준 확정 | 배포 성공 기록과 커밋, 앱·Web 산출물 일치 | 배포 기록 미확보 |
| 1차 소스 대조 | 후보별 위치·이동·제외 이유와 새 알파 기준 차이 | 정적 위치 대조 및 주요 변경 검토 수행. 배포 연결은 남음 |
| 2차 의미 대조 | 같은 키의 목적 일치, 컨테이너·상태 구분, 플랫폼 차이 처리 | 기획 제안과 주요 충돌 정리. 팀 확정·실제 흐름 QA는 남음 |
| 3차 수신 대조 | 시나리오별 발신→GA 수신→내부 조회의 이름·값·건수 일치 | 미실행 |
| 계측 변경 출시 | P0 해결, 적용 대상 화면별 QA, 구버전 호환 및 되돌림 준비 | 미착수 |

수신 대조는 다음 순서로 진행합니다.

1. 같은 테스트 방문의 발신 로그에서 screen_name, screen_instance_id, event_id, 플랫폼·빌드를 확인합니다.
2. GA 디버그 수신에서 대응하는 이벤트를 확인합니다. 원시 내보내기를 사용하는 경우 그 환경의 내보내기 지연도 기록합니다.
3. 내부 수신 저장소에서 같은 event_id의 필드·건수를 확인하고 공통 화면 목록과 조인한 결과까지 확인합니다.
4. 화면별 QA 결과에 빌드·테스트 시각·시나리오·기대값·실제값·증거 위치를 남깁니다. 실패를 고친 뒤 영향받은 흐름을 다시 검증합니다.

출시 후에는 담당자·관찰 기간·누락 및 중복의 판정 기준을 배정합니다. 문제가 생기면 새 수집 경로의 기능 플래그를 원복하고 구버전 수집을 유지할 수 있게 준비합니다. 같은 시각에 두 경로를 켜서 데이터를 중복 적재하는 방식으로 복구하지 않습니다.
