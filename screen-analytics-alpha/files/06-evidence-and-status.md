# 조사 근거와 남은 확인

이번 조사에서는 Bitbucket 원격 브랜치를 갱신하고 고정된 커밋의 소스를 읽었습니다. 이전 작업의 화면 수를 그대로 확정하지 않고, 후보 항목과 변경된 구현을 다시 대조했습니다. 제품 코드 수정, 외부 티켓 등록, 개발자 발송, 배포는 수행하지 않았습니다.

| 플랫폼 | 고정 소스 | 버전·배포 연결 근거 |
|---|---|---|
| AOS | [b135a94143c455b3251c83332ab05451f849f9db](https://bitbucket.org/cre8orclub/c8c-aos/src/b135a94143c455b3251c83332ab05451f849f9db/) | config/app-version.properties의 3.1.0·396. bitbucket-pipelines.yml에 수동 deploy-alpha 경로. 실행 성공 미확인 |
| iOS | [34ad6c9dbe92b49383c8d20ca4eced3f5ca7c8ac](https://bitbucket.org/cre8orclub/c8c-swift/src/34ad6c9dbe92b49383c8d20ca4eced3f5ca7c8ac/) | AppMarketingVersion.xcconfig의 3.0.2. alpha 브랜치에서 Alpha TestFlight 배포. Fastfile은 TestFlight 조회로 빌드번호 발급. 업로드 성공·발급 번호 미확인 |
| Web | [de80fc8d25d499c84f35fa34235cdb57b74d7d04](https://bitbucket.org/cre8orclub/c8c-web/src/de80fc8d25d499c84f35fa34235cdb57b74d7d04/) | alpha/2026.08.AS548. Alpha Build 뒤 수동 Alpha Deploy. 배포 실행·산출물 미확인 |

이전 소스와 비교한 변경 파일은 AOS 855개, iOS 377개, Web 109개입니다. UI 변경 수가 아니며 이동·문서·테스트·기반 코드도 포함합니다. Web의 이전 비교 기준은 당시 stage 커밋이고 이번 기준은 사용자 지정에 따른 alpha 커밋입니다.

이전 후보 741개는 AOS 405개, iOS 216개, Web 120개입니다. 선언 위치가 확인된 항목 653개, 참조만 확인된 항목 77개, 동일 심볼이 없어진 항목 11개로 대조했습니다. 참조에는 경로 문자열·상태 분기 등이 포함되며, 정적 심볼 존재가 실제 진입이나 수신을 증명하지 않습니다.

없어진 항목 중 AOS 프로젝트 지원자 Activity는 현재 Chatty 목적지로, iOS 팀 탭은 독립 TeamListView로 연결되는 것을 확인해 목록을 수정했습니다. 카드 교환·이전 자기소개·디자인 미리보기 등은 삭제·대체 상태를 남겼습니다. 추가로 변경 파일에서 뽑은 이름 후보 139개를 확인해 실제 새 목록, 기존 화면 호스트, 내부 구성, QA 전용 표면을 구분했습니다. 후보 이름의 수를 신규 화면 수로 세지 않습니다. 이 자동 추출은 Screen·Activity·Fragment·View·Page·Route 접미사를 대상으로 하므로 Sheet·Dialog·Controller 등 다른 이름의 새 표면은 누락될 수 있습니다. 플랫폼 개발자는 전체 탐색 구조와 대조해 추가 여부를 확인해야 하며, 이번 후보 분류만으로 전 화면의 완전성을 보장하지 않습니다.

검토 과정에서 원래 초안의 연락처 팔로워·팔로잉 키 누락을 보완했고, 일촌 요청은 같은 탭 안의 구성으로 분류했습니다. 신규 가입 약관과 갱신 약관도 분리했습니다. 독립 팀 목록, 실제 지원자 목적지, 양 플랫폼의 전면 게임 과업을 반영했습니다. Web의 레거시 경로와 실제 알파 접근 여부는 보류 상태로 남깁니다.

현재 앱의 내부 체류시간 계약은 Web에 포함된 OpenAPI 타입과 관련 API 소스에서 보조 확인했습니다. 참고 API는 [stage/2026.08의 085f1bfbbb1671ecbeaa76c2b819cb321a7f0337](https://bitbucket.org/cre8orclub/c8c-api/src/085f1bfbbb1671ecbeaa76c2b819cb321a7f0337/)입니다. 이 커밋의 알파 배포 연결은 미검증이므로 현재 알파 서버 계약으로 확정하지 않습니다. 참고 구현의 저장 테이블은 member_screen_duration_log이며 enum·진입·이탈 시각을 저장합니다. 실제 DB 행이나 데이터 웨어하우스는 읽지 않았습니다.

Web 로직 재현은 원본 함수에 모의 시계·가시성·수신 함수를 연결해 실행했습니다. 확인 결과는 빠른 다른 경로 이동 억제, 숨겨진 마운트의 명시 이벤트 생성, 모듈 시작 시각으로 계산되는 체류 구간, 종료 cleanup의 미전송입니다. hidden 마운트 시험은 현재 함수에 초기 가시성 방어가 없음을 확인한 것이며 실제 WebView의 사전 로딩 동작을 재현한 시험은 아닙니다. 실제 브라우저·기기·GA·DB를 통한 시험이 아니므로 3차 수신 검증으로 계산하지 않습니다.

소스 계약, 웹뷰·수명주기, 목록 누락의 세 관점에서 추가 검토했습니다. AOS proposal_create·proposal_edit가 웹뷰 코드에 나타나는 부분은 exit_process 행동 이벤트임을 다시 확인했으므로, 그 근거만으로 Web의 screen_view와 중복된다고 단정하지 않았습니다. 실제 중복 여부는 QA에서 확인합니다. QAReport의 제품 통계 제외는 DEBUG/QA_TOOLS용 구현에 따른 이 문서의 기획 제안입니다.

남은 확인은 다음과 같습니다.

| 필요한 자료 | 확인 목적 | 그 전까지의 상태 |
|---|---|---|
| 알파 배포 성공 알림 또는 CI 실행 결과 | 실제 배포 커밋·빌드번호·시각 연결 | 최신 알파 브랜치 소스 후보 |
| 설치 앱·Web 배포 식별값 | 테스트 대상과 소스 일치 | 실물 대조 미검증 |
| 알파 GA 속성·스트림·수집 설정 및 수신 접근 | 초기화·자동/수동 수집·실제 이벤트 확인 | 3차 GA 검증 미실행 |
| 내부 수신 환경·조회 경로 | 실제 필드·중복·적재·분석 결과 확인 | 내부 수집 검증 미실행 |
| 테스트 계정과 조건별 흐름 | 회원 상태·권한·레거시 진입·웹뷰 표시 확인 | 조건부 진입 미검증 |

소스 기준표와 핸드오프 문서는 이 상태를 전제로 사용할 수 있습니다. 배포 기준이 확정되거나 수집 로그를 확보하면 관련 차이와 QA 결과를 추가하고, 통과한 단계만 완료로 바꿉니다.

산출물 자동 검증은 184개 키의 고유성, 후보 대응 누락, 링크의 고정 커밋·파일·행 존재, 일부 의미 회귀 사례를 확인합니다. 링크 개수는 각 화면의 의미나 실행 가능성을 자동 증명한 수가 아닙니다. 최종 소스 검토에 따라 AN-03과 AN-04를 함께 배포하도록 묶었으며, 앱·탭 복귀 콜백을 AN-04 수정 및 QA 범위에 추가했습니다.

재개 담당 역할은 배포 증거에 플랫폼 개발·배포 담당, 화면 의미와 누락 확인에 기획·플랫폼 개발, GA 수신에 데이터·QA, 내부 적재에 백엔드·데이터 담당입니다. 담당자 이름과 일정은 팀 배정 전입니다. 배포 성공 기록으로 커밋·빌드번호를 연결하면 소스 차이 대조를 재개하고, 테스트 계정 및 GA·내부 조회 접근이 준비되면 05의 수신 검증을 실행합니다.
