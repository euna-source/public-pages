# 화면명 적용 검증

## 정의서 검증

화면 제목과 개발 키의 중복, 사용자 여정 순서, 화면·행동 구분, 출처 파일·행, 이전 목록의 처리 결과를 대조합니다. 소스가 있다는 것과 해당 알파에서 실제로 진입된다는 것은 구별합니다.

## 개발·QA가 실제로 확인할 항목

| 흐름 | 기대 결과 |
|---|---|
| 신규 이메일 가입 | 이메일→약관→인증→비밀번호→ID→이름이 실제로 나타날 때 각각 한 번. 가입 완료 버튼에 별도 화면 조회 없음 |
| 소셜 가입 | 외부 인증 화면은 앱 화면명에서 제외. 실제 앱 내 약관·ID·이름만 기록 |
| 기존 회원 로그인 | 입력 단계·필요한 2단계 인증·메인만 기록. 가입 단계 끼어들지 않음 |
| 디스커버리→포트폴리오→타인 프로필 | 세 목적지의 제목이 실제 전면 순서와 일치 |
| 내 프로필·타인 프로필 | 소유 맥락에 맞는 제목. 선택 탭과 부모 호스트 중복 없음 |
| 프로필·작업물 작성 | 폼 내부 필드 변경에 화면 수 증가 없음. 독립 첨부 편집 화면에는 새 조회 |
| 채티 목록→프로젝트 대화→지원자 | 목록·대화방·지원자 화면을 구분. 메시지 수만큼 화면 조회가 늘지 않음 |
| 앱·WebView | 동일 전면 화면을 한 발신자만 기록. 사전 로딩은 0건 |
| 뒤로가기·복귀·빈 결과 | 정의한 방문·상태 규칙과 실제 수신 일치 |
| GA 보고서·내부 데이터 | 고정 제목·키·정의 버전의 실제 수신과 집계 확인 |

현재는 제목 정의와 소스 대조, 문서·웹페이지 동작을 검증하는 단계입니다. 제품 코드에 제목을 적용하거나 실제 GA·내부 데이터 수신을 확인한 상태는 아닙니다.

기준 소스는 AOS `b135a9414`, iOS `34ad6c9db`, Front Web `de80fc8d2`입니다. 알파 배포 성공 기록으로 설치본과 소스를 연결한 뒤 위 흐름을 테스트합니다. 실제 회원 상태·권한 때문에 화면이 생략되는 경우 생략된 화면의 조회는 보내지 않습니다.
