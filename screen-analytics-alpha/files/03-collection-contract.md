# 화면 기록과 수신 명세

화면이 실제로 보이는 순간 하나의 방문 정보를 만들고, GA와 내부 분석에 같은 이름과 방문 식별값을 전달합니다. 두 수집 경로의 최종 데이터는 이 식별값으로 대조합니다. 아래는 새로 구현할 계약 제안이며 현재 배포된 API가 아닙니다.

| 항목 | 타입·값 | 규칙 |
|---|---|---|
| screen_name | 문자열 | 공통 목록의 고정 키. 표시명은 목록에서 조회합니다. |
| screen_schema_version | 문자열 | 적용할 정의 버전. 초안은 `alpha-proposal-20260909.1`이며 팀 확정 시 발행 버전을 정합니다. |
| screen_instance_id | 문자열 | 한 번의 실제 방문에 생성하는 불투명 식별값. 같은 방문의 발신·재시도·복귀에는 유지합니다. 사용자 번호를 넣지 않습니다. |
| event_id | 문자열 | 이벤트별 불투명 식별값. 동일 이벤트 재시도에는 같은 값을 유지합니다. GA에서 자동으로 중복 제거된다고 가정하지 않습니다. |
| event_type | 열거형 | 내부 수신에서는 `screen_view`, `screen_resume`, `screen_suspend`, `screen_exit`, `flow_step_view` 등으로 구분합니다. |
| occurred_at | UTC 시각 | 내부 수신의 발생 시각. 수신 서버는 received_at을 별도로 기록합니다. |
| platform | aos / ios / web | 웹뷰에서 네이티브 수집기를 통해 보내면 호스트 플랫폼입니다. 독립 브라우저는 web입니다. |
| surface | native / webview / browser | 실제 화면 구현 환경입니다. |
| environment | alpha | 운영과 분리합니다. 실제 알파 GA 속성·스트림·백엔드 연결을 확인해야 합니다. |
| app_version·app_build | 문자열 | 호스트 앱의 실제 설치 버전·빌드. 독립 브라우저에서는 해당 없음으로 내부에 저장하고 GA에는 생략합니다. |
| web_build | 문자열 | 실제 Web 배포 식별값. 웹뷰와 브라우저에서 필수입니다. |
| previous_screen | 문자열 | 직전의 실제 주 목적지. 처음 방문에는 GA에서 생략하고 내부에는 null로 둡니다. |
| navigation_type | enter / forward / back / deeplink / reload | 이동 원인입니다. 단순 포그라운드 복귀는 별도 screen_resume입니다. |
| entry_point | 합의한 열거형 | home / search / profile / chat / notification / external / other 등으로 관리합니다. 자유 입력 URL을 넣지 않습니다. |
| content_state | ready / empty / error | 화면이 보일 때의 상태입니다. 로딩 완료 여부와 정상 빈 결과를 구분합니다. |
| 화면별 속성 | 열거형·수치 | profile_owner, view_mode, content_type, mode, room_type, step_name 등을 해당 화면 명세에 따라 추가합니다. |

기존 AOS `screen_id`에는 회원 UID나 콘텐츠 번호가 들어갑니다. 새 화면 이름이나 방문 식별값을 그 필드에 덮어쓰지 않습니다. 콘텐츠별 분석이 필요하면 별도 대상 식별자 계약을 합의하고, 개인 식별값·이메일·전화번호·검색 자유문자·토큰·전체 URL을 화면명이나 방문 식별값에 포함하지 않습니다.

네이티브 화면은 GA 표준 `screen_view`에 `screen_name`과 공통 속성을 넣습니다. 독립 Web은 `page_view`에 공통 `screen_name`을 사용자 정의 속성으로 넣고, 페이지 제목은 실제 페이지 정보로 유지하고, URL은 민감 쿼리와 개별 식별값을 제거하는 정책을 적용합니다. 기본 측정기준으로 같은 분석을 할 수 있는지 먼저 확인하고, Web의 공통 속성이 보고서에 별도로 필요하면 이벤트 범위의 맞춤 측정기준으로 등록합니다. 통합 집계에서는 앱 SDK가 저장한 실제 화면명 필드와 Web의 공통 속성을 QA 수신 표본으로 확인해 연결합니다. 원시 내보내기의 키가 SDK 입력명과 같다고 가정하지 않습니다. 기존 Web `screen_view`와 새 `page_view`를 방문 수에 동시에 더하지 않습니다. [Firebase 화면 기록](https://firebase.google.com/docs/analytics/screenviews), [GA SPA 측정](https://developers.google.com/analytics/devguides/collection/ga4/single-page-applications).

웹뷰에는 다음 절차를 제안합니다.

1. 앱이 Web에 호스트 버전·빌드, 웹뷰 식별값, 주 화면 여부, 보임·가려짐 상태와 수집 프로토콜 지원 버전을 전달합니다.
2. Web이 경로와 실제 표시 콘텐츠가 정해졌을 때 공통 이름과 새 방문 식별값을 만듭니다. 미리 준비한 이웃 WebView와 내장 모듈에서는 방문을 만들지 않습니다.
3. 지원하는 앱에서는 Web이 새 방문 정보를 네이티브 수집기로 전달합니다. 네이티브는 같은 이벤트를 GA와 내부 수신 경로로 각각 전달하며, Web은 직접 GA 방문을 추가하지 않습니다.
4. 전달 확인과 재시도에 event_id를 유지합니다. 네이티브 호스트의 화면 조회는 해당 Web 방문을 대체해서 보내지 않습니다.
5. 구버전 앱은 기능 지원 여부로 구분합니다. 기존 직접 Web 수집을 유지하는 구간에는 legacy 표시를 두고 새 정의 통계에서 구분합니다. 단순 전달 시간 초과만으로 두 경로를 모두 발신하는 fallback은 사용하지 않습니다.

현재 코드의 웹뷰 가시성 콜백을 활용할 수 있으나, 위 방문 전달·확인 계약은 새로 구현해야 합니다. 표준 수집 주체를 결정하기 전에 모든 자동 수집을 일괄 해제하지 않습니다. 자동·수동 기록을 테스트에서 대조한 뒤, 명시적으로 소유하는 화면의 자동 수집 중복을 조정합니다.

내부 분석에는 새 수신 계약이 필요합니다. 현재 `/v1/api/members/screen-duration-logs`는 정해진 enum과 진입·이탈 시각을 받으며, 일반적인 공통 화면명·방문 식별값을 저장하는 계약이 아닙니다. enum을 임의 문자열로 바꾸거나 같은 필드에 새 화면명을 보내면 호환이 깨질 수 있습니다.

추가 API로 `POST /v2/api/analytics/screen-events`를 제안합니다. 이 경로는 현재 존재가 확인된 경로가 아니며 백엔드 팀이 최종 확정합니다. 로그인·익명 수집 경로와 동의 정책은 기존 인증 체계에 맞추고, 수신 데이터에는 위 공통 필드와 허용된 속성만 저장합니다. 서버는 발신 환경과 버전을 검증하고 `(environment, event_id)`에 대한 중복 삽입을 막습니다. 재시도는 제한된 보관 기간·횟수와 순서를 가지며, 수신 실패를 성공으로 처리하지 않습니다.

기존 체류시간 API는 구버전 호환용으로 유지합니다. 새 방문 집계는 screen_view만 사용하며 screen_enter·screen_exit·작성 완료·작성 중단을 더하지 않습니다. 같은 방문의 foreground 구간은 단조 시계로 측정해 합산하고, screen_suspend와 screen_resume은 조회 수를 늘리지 않습니다. 중첩 화면과 같은 종류의 콘텐츠 연속 방문은 이름만으로 저장하지 않고 screen_instance_id로 구분합니다.

QA에서는 GA의 원시 이벤트와 내부 수신 결과를 event_id로 대조합니다. GA 사용자 정의 식별값은 검증·원시 조회용으로 사용하고 고유값이 많은 식별자를 일반 대시보드 분류로 등록하지 않습니다. GA 표준 보고서의 고유 사용자·참여시간과 내부 정의는 계산법이 다를 수 있으므로 같은 값이라고 약속하지 않습니다.

정확한 이름별 집계는 공통 목록과 조인한 분석 뷰에서 수행합니다. 알파 이벤트, 구버전 이벤트, 컨테이너·행동 이벤트를 분리한 뒤 방문 수·사용자 수·이동 경로·체류시간을 산출합니다. 내부 화면 이름 정본의 관리 책임자와 키 변경 승인자를 팀에서 배정합니다.

맞춤 측정기준은 설정 후 보고서 반영까지 시간이 걸릴 수 있습니다. 수신 검증과 보고서 표시 검증을 나누고, 방문·이벤트별 고유 식별값을 일반 분류용 맞춤 측정기준으로 등록하지 않습니다. [GA 맞춤 측정기준 안내](https://support.google.com/analytics/answer/14240153).
