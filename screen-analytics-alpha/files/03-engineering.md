# 개발 적용 규칙

화면 정의 목록의 고정 제목을 전송합니다. 클래스명이나 기능명으로 화면 제목을 다시 만들지 않습니다. 기본 키·제목·버전은 한 사전으로 관리하고 iOS·AOS·Web이 같은 사전을 사용합니다.

## 실제 전송 예시

마이에서 내 포트폴리오 탭이 전면에 나타난 경우 앱의 전송값은 다음과 같습니다. 코드 예시는 논리 페이로드이며 SDK별 호출 인자는 해당 플랫폼 구현에 맞춥니다.

```json
{
  "event_name": "screen_view",
  "screen_name": "마이 · 포트폴리오",
  "screen_key": "my_portfolios",
  "screen_definition_version": "screen-titles-20260909.2",
  "environment": "alpha"
}
```

독립 브라우저에서 공유 포트폴리오 상세를 연 경우에는 다음과 같이 보냅니다.

```json
{
  "event_name": "page_view",
  "page_title": "공유 · 포트폴리오 상세",
  "screen_key": "share_portfolio",
  "screen_definition_version": "screen-titles-20260909.2",
  "environment": "alpha"
}
```

브라우저 탭 제목·검색용 메타 제목은 별도로 유지할 수 있습니다. GA에 전송하는 `page_title`은 이 문서의 고정값으로 명시합니다. 개인 이름·콘텐츠 제목·검색어가 섞인 문서 제목을 그대로 분석 이름으로 사용하지 않습니다. 기본 페이지 조회나 SPA 자동 수집과 명시 전송이 겹치는지도 확인합니다.

## 화면 이름을 정하는 순서

1. 앱 실행 후 실제 전면 목적지를 확인합니다. 비로그인 시작, 튜토리얼, 메인, 딥링크 중 실제 나타난 화면을 고릅니다.
2. 목적지가 프로필이면 내 프로필인지 타인 프로필인지 구분합니다.
3. 탭이 있는 화면이면 현재 선택된 탭이 제목을 소유합니다. 부모 호스트의 조회를 함께 보내지 않습니다.
4. 독립 과업 시트가 전면에 열리면 그 시트 이름으로 전환합니다. 단순 확인 팝업·키보드는 현재 화면 이름을 유지합니다.
5. 새로운 목적지가 실제로 표시된 시점에 한 번 전송합니다. 프리로드·재렌더·같은 탭 재선택에는 보내지 않습니다.

## 같은 화면과 새 방문

| 상황 | 화면 제목 | 조회 처리 |
|---|---|---|
| 파인더에 검색어 입력 | 파인더 · 검색 유지 | 입력마다 보내지 않음 |
| 검색 결과의 크리에이터→포트폴리오 탭 전환 | 각 결과 화면 제목 사용 | 전면 탭 전환 때 한 번 |
| 결과 없음·필터 변경·더 불러오기 | 현재 결과 제목 유지 | UI 상태 변화만으로 추가 조회 안 함 |
| 프로필 A→프로필 B 전면 전환 | 크리에이터 화면 제목 유지 | 다른 프로필이 전면에 확정되면 새 방문 |
| 포트폴리오 상세 A→B | 포트폴리오 · 상세 유지 | 다른 콘텐츠가 전면에 확정되면 새 방문 |
| 앱을 잠깐 내렸다가 같은 화면 복귀 | 현재 제목 유지 | 같은 방문의 조회 추가 없이 체류 구간 재개 |
| 다른 화면을 방문한 뒤 뒤로 돌아옴 | 돌아온 화면 제목 | 새 방문 한 번 |
| 같은 작성 폼 안에서 입력 블록 펼침 | 현재 작성 화면 제목 유지 | form_step·active_field로 구분 |

앱·웹뷰의 발신 책임, 방문 식별값, 체류시간·중복 방지의 상세 구현은 기존 수집 분석 부록을 참고합니다. 이번 정의서가 우선하는 변경은 화면 제목과 화면 경계입니다. 이전 영문 `screen_name`을 과거 데이터 전체에 한국어로 일괄 치환하지 말고, 플랫폼·발신 위치·버전별로 연결합니다.

## 내부 데이터에도 같은 제목 연결

내부 로그의 화면 식별값은 `screen_key`, 표시명은 이 정의서의 제목으로 연결합니다. 기존 체류시간 enum을 바꾸는 것만으로 모든 새 화면이 수집된다고 가정하지 않습니다. 새로운 수신 계약과 기존 계약의 호환 작업은 별도 개발 항목입니다.

구현 완료는 제목 사전 적용, 실제 화면 전환 수와 이벤트 수의 일치, 앱·WebView 중복 없음, GA와 내부 조회 결과 확인 뒤에 판정합니다. 문서 작성과 페이지 게시만으로 수집 구현 완료를 표시하지 않습니다.
