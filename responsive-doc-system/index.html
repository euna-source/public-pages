01

양식은 작게, 본문은 유연하게

모든 기획을 같은 긴 목차에 넣지 않습니다. 문서의 목적과 상태는 공통으로 표시하고, 흐름·규칙·화면 문구·예외·검수 기준은 필요한 만큼 조합합니다.

추천: 차분한 구조 + 절제된 브랜드 그린.
이미 쓰는 브랜드는 이어가고, 본문 가독성과 정보의 위치를 일관되게 만듭니다. ‘정책 승인’과 ‘개발 완료’는 서로 다른 상태로 표시합니다.

처음 읽는 사람에게는 목적과 흐름을, 다시 찾는 사람에게는 목차와 조항 링크를 제공합니다. 요약과 상세의 수치는 한 곳에서 관리합니다.

근거: GitHub의 조건부 문서 구성 · Diátaxis의 유연한 적용

02

함께 설계할 여섯 영역

모바일 깨짐은 레이아웃 문제일 수 있지만, 반복 질문은 내용·상태·버전의 문제일 수도 있습니다.

내용의 기준
사실·제안·확정의 구분. 구현할 동작, 조건, 예외, 용어.
구조와 탐색
공통 머리말, 읽기 순서, 목차, 제목이 바뀌어도 유지되는 조항 ID.
시각적 위계
역할별 글꼴·크기·색상. 읽는 폭과 비교하는 폭의 분리.
반응형과 조작
표의 비교축, 단계의 순서, 키보드·확대·터치에서의 접근.
개발 전달
요구사항과 화면·문구·결정·수용 기준의 연결. 승인과 구현 상태 분리.
운영과 검사
정본, 변경 이력, 공유 권한, 발행 전 반복 검사.

05

기본 양식의 읽기 순서

공통 머리말은 유지하고, 본문은 필요한 모듈만 씁니다. 짧은 변경 공지에 긴 배경·페르소나·여정 작성을 강요하지 않습니다.

  1. 이번에 알아야 할 것

    제목, 한 문장 목적, 범위·제외, 적용 버전, 문서 수정일, 책임자, 결정 상태. 개발 전달 시 구현·검증 상태 추가.

  2. 핵심 흐름 또는 규칙

    언제, 누가, 무엇을 하면 어떤 결과가 생기는지. 일정이면 순서로, 수치면 비교표로 표현합니다.

  3. 구현할 상세와 예외

    화면·문구·데이터는 해당 규칙 옆에. 필수 예외를 문서 끝이나 닫힌 영역에 숨기지 않습니다.

  4. 확인 가능한 완료 조건

    정상·실패·경계 조건의 기대 결과. 요구사항 ID와 검수 항목을 연결합니다.

  5. 남은 결정과 변경 근거

    질문, 현재 제안, 영향받는 요구사항, 결정 담당과 이력. 선택 항목은 생략해도 되지만 필수 정보의 미정은 표시합니다.

07

가이드를 지킬 수 있는 제작 방식까지

첫 버전은 공통 머리말 하나와 요약·규칙·예외·검수 네 모듈로 시작합니다. 내용과 공통 스타일을 분리하고, 반복 값은 한 곳에서 관리합니다. 모든 문서를 한 번에 재제작하지 않습니다.

  1. 대표 구간 두 개에 적용

    정책 설명과 복잡한 항목 대장에 먼저 적용합니다. 같은 내용으로 기존 문서와 새 양식을 비교합니다.

  2. 화면이 버티는지 검사

    320·360·390·440·768·1440px, 확대, 키보드, 긴 URL, 폰트 실패, JavaScript 없음, 인쇄. 가로 넘침·앵커 가림·내용 누락을 확인합니다.

  3. 개발자가 답을 찾는지 확인

    이번 변경, 예외, 미결정, 완료 조건을 찾게 합니다. 찾는 시간·오답·추가 질문을 비교하고, 효과가 확인된 모듈부터 늘립니다.

현재는 제작 전 제안입니다.
이 비교 시안의 작동 확인과 실제 개발자 사용성 검증은 다릅니다. 기존 문서의 재작업 감소나 이해도 개선은 아직 측정하지 않았습니다.

최신 정본과 개발 합의본의 링크를 구분합니다. 공개 문서는 비로그인 접근을 확인하고, 기밀 문서는 인증된 경로로 공유합니다. 정책 결정이 질문의 주원인이라면 시각 디자인보다 승인 절차를 먼저 개선합니다.

08

조사에서 가져온 원칙

공식 원문 확인일 2026.09.23. 홈페이지의 인상과 업무 문서의 사용 규칙을 구분했습니다. 아래 사이트의 모바일 성능을 순위화한 조사는 아닙니다.

  • Linear 홈페이지·업무 흐름 ↗핵심 설명 가까이에 실제 제품 예시.
  • Stripe Checkout 문서 ↗선택지와 비교 기준을 연결.
  • Vercel Geist 타이포 ↗여러 줄 본문과 단일 행 라벨 구분.
  • IBM Carbon 타이포 ↗업무용과 표현용 스케일을 구분.
  • Notion Help ↗주제 탐색과 검색을 함께 제공.
  • GOV.UK 아코디언 ↗모두 읽어야 할 내용은 숨기지 않기.
  • Write the Docs ↗문서에도 버전·리뷰·검사 적용.
  • 과업 기반 사용성 검증 ↗선호와 실제 수행 결과를 구분.

디자인 체계의 제작 전 제안입니다. 예시는 가상이며 실제 서비스의 확정 정책이 아닙니다.
