  1. 01 / 목적

    독자가 무엇을 결정해야 하나요?

    승인을 받는 문서, 동작을 구현하는 문서, 특정 항목을 찾아보는 문서는 본문 순서가 달라야 합니다.

  2. 02 / 구조

    가장 가까운 템플릿을 하나 고릅니다.

    공통 머리말을 채우고 필요한 모듈만 붙입니다. 빈 섹션을 양식 때문에 남기지 않습니다.

  3. 03 / 검수

    실제 내용으로 두 테마와 좁은 화면을 확인합니다.

    가장 긴 제목, 긴 예외, 빈 결과, 오류를 넣어 봅니다. 예시가 잘 보이는 것만으로 문서가 완성되지는 않습니다.

원본의 목적을 유지하면서 문서 구조만 정리하는 적용 방향
기존 문서 권장 구조
명예의 전당 운영 타임라인 + 단계별 대상·담당·진입/종료 조건. 날짜와 기간의 관계를 유지합니다.
베스트 크리에이터 기능 명세 + 산정 규칙·제외·회수 예외 + 미결 결정. 같은 기준값을 여러 곳에서 따로 관리하지 않습니다.
앱푸시·알림 검색 가능한 목록 + 항목 상세. 목록은 비교 필드만, 상세는 조건·문구·예외·변경 이유를 담습니다.
토스트 문구 고유 ID가 있는 문구 목록 + 트리거·노출 조건·액션·문구 상태. 정책과 구현 여부를 별도 표시합니다.
