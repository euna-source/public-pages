어떤 요청인가요?

실제 대화에서는 메뉴를 고르지 않아도 됩니다. 요청 내용을 읽고 필요한 흐름으로 들어갑니다.

UX·문구

“방문자에게 보이는 빈 화면 문구를 고쳐줘.”

역할·상태를 확인하고 문구 제작과 검증으로 이어갑니다.

    지금 살펴보는 단계

    읽는 사람과 현재 상태 확인

    방문자에게 등록 권한이 있는지, 정말 비어 있는 상태인지 확인합니다.

    ↑꺼낼 지식
    역할별 권한과 현재 문구 기준.
    ↓남길 근거
    이번 수정 대상과 적용할 역할·상태.

    대상과 상태가 분명하면 다음으로 갑니다.

    진행 경계 · 권한이 없는 사람에게 등록을 권하지 않습니다.

    작은 일은 단계를 합치고, 이미 끝난 일은 건너뜁니다. 검증에서 문제가 보이면 필요한 앞 단계로 돌아갑니다.

    먼지맵과 연결하는 방식

    다시 쓸 이유가 남는 지식

    워크플로는 언제 무엇을 찾을지 정합니다. 먼지맵의 활용 이력은 어떤 지식이 어느 업무 판단에 쓰였는지 이어 줍니다.

    이번 판단 → 실제 확인 → 다시 볼 조건
    그 조건이 다음 업무의 검색 출발점이 됩니다.

    01
    원문은 근거로대화·문서의 출처와 맥락을 보존합니다. 같은 원문을 새 문서에 반복해서 복사하지 않습니다.
    02
    현재 기준은 판단에지금 유효한 결정과 적용 범위를 확인합니다. 바뀐 기준은 옛 기록과 구분해 연결합니다.
    03
    활용과 결과는 따로읽은 것, 판단에 쓴 것, 효과를 확인한 것은 다릅니다. 실제 적용한 업무·단계와 확인 결과만 남깁니다.

    다시 볼 조건의 예시
    UX·문구 / 빈 상태 / 수정 권한 없는 방문자 / 다음 행동을 정할 때

    자동 진행의 기준

    자동 진행과 확인의 경계

    상황에 따른 진행과 기록 기준
    바로 진행대상과 요청이 분명한 초안·수정·검증은 필요한 단계부터 처리합니다.
    짧게 질문이어 할 대상이 둘 이상이거나 중요한 선택·외부 변경 권한이 빠졌을 때, 그 부분만 묻습니다.
    필요한 것만 기록판단을 바꾼 근거·새 결정·정정·검증 결과와 다시 쓸 조건을 남깁니다. 중복 요약이나 근거 없는 교훈은 늘리지 않습니다.

    평소처럼 “이 문구 고쳐줘”, “측정 정의 이어서 정리해줘”라고 시작하면 됩니다. 단계 선택과 근거 찾기는 맡기고, 결과가 의도와 다르면 그 부분을 바로잡아 주세요.

    이 안내는 비식별 예시입니다. 실제 기록은 공개하지 않습니다. 이번에 정한 방식은 기존 활용 이력의 업무·단계 표기이며, 전용 단계 필터나 자동 분류 통계를 뜻하지 않습니다.

    일이 끝났다는 근거와 지식이 도움이 됐다는 근거를 구분합니다.
