9/28 정기미팅 — 명예의 전당과 채팅방 보관함

음성 원문은 받아쓰기 전문입니다.

2026년 9월 28일 정기미팅을 정리한 회의록입니다. 제공된 음성메모 받아쓰기 내용을 기준으로 작성했으며, 음성 원본과 대조하지 못한 이름·일정·세부 규칙은 확인 항목으로 남겼습니다.

한 줄 요약

내 포트폴리오에도 리스펙트 수를 표시하고 보관함의 파일 표시명과 저장명을 분리하기로 했으며, 게시판 배포 일정과 명예의 전당 운영 규칙은 추가로 정리합니다.

참석자(추정)

전사문에 화자 구분이 없어 참석자 수와 실명을 확정할 수 없습니다. 기획·디자인 공유, iOS·Android·백엔드 구현에 관한 발언은 확인되지만, 각 역할을 특정 화자에게 배정할 수는 없습니다.

대표님과 일부 팀원 이름이 언급되지만, 이름이 나왔다는 이유로 참석자로 포함하지 않았습니다. 아래 할 일의 담당자는 별도 지정이 확인되지 않아 미정으로 두었습니다.

결정된 것

이 절은 회의에서 합의한 동작과 진행 방향을 정리합니다. 세부안이 남은 항목은 해당 문장에 표시했으며, 그대로 개발 명세로 확정할 수 없는 내용은 ‘못 정한 것’에서 별도로 다룹니다.

내 포트폴리오 리스펙트 표시

  • 기존에는 자신에게 리스펙트를 줄 수 없다는 이유로 내 포트폴리오의 버튼을 숨겼습니다. 명예의 전당 집계와 연결해 받은 리스펙트 수를 확인할 수 있도록, 다른 사람의 포트폴리오와 동일하게 버튼과 개수를 표시하는 방향으로 정리했습니다.
  • 자신의 포트폴리오에서 리스펙트 버튼을 누르면 줄 수 없다는 안내 토스트를 표시합니다. 실제 리스펙트를 부여하지 않습니다. 안내 문구는 취지가 정해졌으며 최종 문장은 별도로 정리합니다.
  • 리스펙트를 준 사람의 목록은 기존처럼 포트폴리오 상세에서 확인합니다. 최초에 제안된 새 바텀시트 연결을 추가 확정한 것은 아닙니다.
  • 영감의 좋아요 동작은 유지합니다. Android와 iOS 양쪽의 적용 가능 여부를 확인하기로 했습니다.

명예의 전당 이벤트 페이지 구성

  • 이벤트 페이지에는 배너와 배경 영상이 들어갑니다. 회의에서 보여준 영상은 최종본이 아니므로 교체를 고려해 구현합니다.
  • 설명과 안내 문구, 정보 아이콘을 눌렀을 때의 설명은 별도 데이터 연동 없이 정적 콘텐츠로 구성합니다.
  • 이벤트 설명 페이지에서 명예의 전당으로 이동하는 링크 또는 버튼을 제공합니다. 작품 등록은 기존 플러스 버튼을 사용하며, 이벤트 페이지 안에 별도 참여 기능을 추가하는 방향은 아닙니다.
  • 회차별 금액과 조건처럼 달라질 수 있는 정보는 이벤트 설명 페이지에서 안내하는 방향입니다. 외부 페이지 활용 범위와 웹뷰·네이티브 화면 경계는 추가 확인이 필요합니다.
  • 후보자가 없을 때의 화면도 추가하기로 했습니다. 집계 중 안내가 예시로 제안됐으며, 최종 문구와 노출 조건은 남아 있습니다.

보관함 썸네일과 파일 표시명·저장명 분리

  • 채팅방 메뉴에서 들어가는 보관함은 기존 리스트형에서 썸네일 중심으로 변경합니다. 링크의 오픈그래프 표시도 논의됐으나 세부 규격은 확인이 필요합니다.
  • 서버에 저장하는 파일은 난수 기반 이름을 사용하고, 이용자에게 보여 주는 파일명은 별도로 관리하는 방향으로 정리했습니다. 표시명을 받는 API 작업이 필요하다는 설명이 있었습니다.
  • iOS는 가져올 수 있는 원래 파일명을 표시하고, 다운로드할 때도 해당 이름을 유지하는 방향입니다.
  • Android는 회의에서 원래 파일명을 가져오기 어렵다고 설명됐으므로, 별도 생성 규칙을 사용합니다. 이는 회의에서 공유된 구현 제약이며 이번 회의록 작성 과정에서 실제 코드를 확인한 결과는 아닙니다.
  • Android 파일명은 논의 후반에 파일 종류 접두어를 빼고 날짜·시간과 랜덤 코드 네 자리를 조합하는 방향으로 모였습니다. 연도 자릿수, 초 포함 여부, 구분자, 랜덤 코드 문자 종류는 정확한 규칙을 다시 전달하기로 했습니다.
  • 화면에 보이는 파일명과 다운로드 파일명은 일치시키는 방향입니다. 다만 OS별 원본명 처리와 중복 처리의 구체적인 구현은 별도로 정리합니다.
  • 같은 이름 뒤에 1, 2를 붙이기 위해 전체 파일을 조회하는 방식은 개발 부담이 있어 채택하지 않았습니다. 파일들을 구분할 수 있게 하되, 이 규칙 때문에 주요 기능 개발이 지연되지 않도록 구현 공수를 우선 고려합니다.

보관함 공지 탭 숨김과 게시판 도입

  • 현재 공지에는 상세 화면과 게시물 관리 기능이 없어, 보관함에서 과거 공지 목록만 보여 주는 효용이 작다는 의견이 모였습니다.
  • 논의 말미에는 보관함의 공지 탭을 우선 노출하지 않고, 게시판이 도입될 때 다시 구성하는 방향으로 정리했습니다. 기존 채팅방 공지 기능 자체를 없애기로 한 것은 아닙니다.
  • 프로젝트 운영에 게시판이 필요하다는 데 공감했습니다. 다만 10월 중순 배포에 넣기 위해 기존 기능을 빼는 교환안은 확정되지 않았습니다.
  • 답글 달기는 공수 대비 중요도가 높다는 의견이 있었고, 이를 제외하기로 결정하지 않았습니다. 사진·동영상 동시 업로드 등 다른 기능을 빼도 게시판 개발 시간을 확보하기 어렵다는 설명이 있었습니다.

공유 버튼·위젯의 진행 방향 — 세부 디자인 확인 필요

  • 프로젝트·라운지 공유 버튼의 위치를 Android와 iOS에서 맞춰야 합니다. 첫 화면에서 공유 기능에 접근할 수 있는 배치와, 알림을 벨 아이콘으로 표현하는 안을 논의했습니다. 정확한 위치는 디자인에서 정리합니다.
  • 위젯은 포트폴리오 보기·포트폴리오 올리기·영감 올리기 등 개발 중인 바로가기 구성을 우선 적용하고, 이후 사용성을 보며 변경하는 방향에 동의했습니다. 기능 이름은 전사 표현이 불명확하므로 티켓과 대조가 필요합니다.
  • 위젯은 10월 6일 배포분에 포함해야 한다는 발언이 있었습니다. 정확한 티켓과 배포 범위는 확인이 필요합니다.

캠페인 개시 전 앱 배포·안정성 확인

  • 캠페인을 여는 날보다 최소 하루 전에 운영 환경에 앱을 배포하고 안정성을 확인해야 한다는 기준을 재확인했습니다.
  • 화요일 앱 배포, 수요일 캠페인 개시가 논의됐습니다. 회의 날짜와 10월 5일 휴일 언급을 기준으로 보면 각각 10월 6일과 10월 7일을 가리키는 것으로 보입니다. 캠페인 시작일 자체는 유동적이며 확정 일정으로 보지 않습니다.
  • 크리에이터 활동 점수는 해당 집계 기간의 활동을 기준으로 하고, 이전부터의 전체 누적 점수를 그대로 사용하는 것은 아니라는 점을 확인했습니다.

못 정한 것

파일명 세부 규칙

날짜·시간과 랜덤 네 자리라는 방향은 나왔지만, 바로 구현할 수 있는 단일 형식은 확정되지 않았습니다. 연도를 두 자리로 할지, 초까지 넣을지, 구분자를 어디에 넣을지, 랜덤 코드가 영문 대문자만인지 숫자를 포함하는지 확인해야 합니다. 네 자리 랜덤 코드의 충돌 처리도 정해지지 않았습니다. 파일 종류 접두어를 붙이는 초기안과 일련번호를 붙이는 중간안을 최종안으로 섞지 않습니다.

iOS에서 원본명이 같은 파일을 여러 번 올렸을 때의 처리와, Android 생성명에 쓰는 시각이 업로드·파일 생성·다운로드 중 어느 시점인지도 명확한 확인이 필요합니다.

게시판 배포일과 구현 범위

10월 중순 배포 포함, 다음 정기 배포, 10월 중간 별도 배포가 모두 논의됐으며 마지막에는 다시 이야기하기로 했습니다. 전사에는 중순 배포일이 15일과 16일로 혼재하므로 정확한 날짜를 확정하지 않습니다. 후속 배포의 30일 언급도 게시판 확정 일정은 아닙니다.

게시판은 프로젝트를 포함한 채팅방 전반에 제공하는 방향이 언급됐습니다. 일반 참여자의 글 작성, 방장만 공지 지정, 기존 대화를 게시물로 전환하는 기능이 논의됐지만, 이번 구현 범위와 권한으로 모두 확정된 것은 아닙니다.

명예의 전당 1회차 대상과 재수상 정책

  • 1회차 작품 범위: 집계 기간 안에 올린 포트폴리오만 대상으로 하는 기존안 대신, 첫 회차에는 기존 작품도 포함하자는 의견이 나왔습니다. 포함 범위와 리스펙트 집계 기준을 최종 확인해야 합니다.
  • 같은 작품의 재수상: 한 번 수상한 포트폴리오는 제외하자는 의견과 반복 수상이 가능하자는 의견이 갈렸습니다. 다른 작품에 기회를 주자는 근거가 있었으나 운영하면서 판단하자는 발언도 있어 최종 규칙은 남아 있습니다.
  • 상금: 150만 원이라는 문구가 언급됐지만 대표님과 추가 논의하기로 했습니다. 확정 상금으로 기록하지 않습니다.
  • 빈 상태: 후보자가 없을 때와 단순 집계 중일 때를 같은 안내로 처리할지, 각각 다르게 보여 줄지 정해야 합니다.
  • 홍보·개시: 공식 채널과 커뮤니티 홍보, 관계자 안내 방식이 아직 정리되지 않았습니다. 확정 개시일에 맞춰 앱 배포와 운영 준비를 연결해야 합니다.

명예의 전당 진입·연출·배너 노출
