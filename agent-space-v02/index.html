누가 어떤 상태에서 읽는지 봅니다

등록된 자료가 없는 방문자 화면입니다. 방문자가 할 수 있는 행동과 알려야 할 사실을 정합니다.

이번 단계에서 확인할 것
방문자 권한 · 비어 있음과 불러오기 실패 구별

    캐릭터와 역할

    캐릭터의 이름과 거처는 이어집니다. 실제로 일을 맡으면 담당과 실행 기록이 연결됩니다. 쉬는 모습과 실제 업무 수행은 구별합니다.

    아테나 · 대표 먼지

    현재 역할을 이어가는 중심

    아테나는 목표와 판단의 자리입니다. 대표 먼지는 사용자가 말을 걸고 진행과 결과를 받는 얼굴입니다.

    같은 과업의 책임을 공유합니다. 둘 사이에 별도 승인을 반복하는 단계는 만들지 않습니다.

    먼지요정들

    필요할 때 참여하는 검토 관점

    결정, 다른 전제, 누락, 실행 제약, 실패 가능성을 봅니다. 색과 이름으로 맡은 관점을 함께 표시합니다.

    읽고 검토한 발견을 반환합니다. 요정 하나의 답변 완료와 전체 검증 통과를 구별합니다.

    작은 작업 먼지

    임무별 일꾼 · 새 연결 제안

    자료를 찾거나 독립된 초안을 만드는 역할을 맡습니다. 실제 작업 단위가 있을 때만 담당 표시를 붙입니다.

    지시에는 목표, 허용 범위, 결과 형식과 끝낼 조건이 있습니다. 최종 수정은 메인이 맡습니다.

    키티 · 다음 동료

    제작·표현 역할 후보 · 미등록

    첫 후보는 글과 화면의 표현을 다듬는 동료입니다. 현재는 역할 제안이며 실제 업무로 적합성을 확인해야 합니다.

    외형이나 입주만으로 권한을 얻지 않습니다. 반복 산출과 검증을 근거로 능력을 등록하고 필요한 임무에 참여합니다.

    첫 연결은 먼지부터 시작합니다. 새 캐릭터를 더해도 기억 서가·조사대·제작실의 기능과 위치는 이어집니다.

    속도와 품질

    속도는 필요한 단계만 거치는 데서, 품질은 알맞은 근거와 검증에서 얻습니다. 일꾼 수를 품질 점수로 쓰지 않습니다.

    같은 실패 반복, 필수 근거 부재, 권한 경계

    Fast에서도 코드 수정의 독립 검토와 실제 결과 확인은 유지합니다. 외부 행동의 결과가 불명확하면 먼저 조회하고 중복 실행을 막습니다.

    동시에 조사할 수 있어도 같은 결과물을 동시에 고치지는 않습니다. 이 설계의 최종 작성자는 메인 한 명입니다.

    구체적인 소요 시간과 품질 개선은 아직 측정하지 않았습니다. 단순 문구 2분·QA 준비 10분·방향 조사 20분은 초기 상태 점검 시점 제안이며 완료 보장이 아닙니다.

    첫 연결과 확장

    지금 확인할 수 있는 상태부터 연결합니다. 세부 활동과 다음 캐릭터는 실제 사건과 역할 근거가 마련된 만큼 확장합니다.

    01 / 첫 연결

    먼지와 아테나

    현재 작업의 시작, 진행, 종합, 답변, 오류를 연결합니다. 결과와 필요한 입력을 글로도 확인합니다.

    통과 기준: 같은 과업의 실제 시작과 결과가 이어지고, 쉬는 동안 모델을 호출하지 않습니다.

    02 / 기능 연결

    기억과 작업의 이동

    검색·읽기·제작·검토를 구별할 수 있는 사건이 생기면 해당 자리의 움직임을 켭니다.

    통과 기준: 세 업무의 표시와 실제 도구 결과가 맞고, 부분 실패·중단·오래된 관측을 구별합니다.

    03 / 입주 확장

    키티와 다음 캐릭터

    상주 명부와 능력 계약을 연결합니다. 임무가 끝나면 거처로 돌아가며 다음 요청에서 정체성이 이어집니다.

    통과 기준: 실제 산출·검증·채택이 있고, 역할과 권한을 설명할 수 있습니다.

    리서치에서 가져온 것.

    공간의 생명감, 기능 연결, 병렬 작업의 조건을 함께 살폈습니다. 이 공간이 목록보다 이해하기 쉽다는 가설은 실제 사용자 비교가 남아 있습니다.

    Generative Agents ↗

    기억과 계획이 이어지는 존재에서 상주감을 참고합니다. 연구가 평가한 것은 사회행동의 그럴듯함입니다.

    적용 한계: 업무 생산성 개선을 입증한 실험은 아닙니다.
    AI Town ↗

    바꿀 수 있는 캐릭터·지도와 시뮬레이션 정지 기능을 참고합니다. 생활동작은 가볍게 유지하는 방향입니다.

    적용 한계: 사회 시뮬레이션의 구조를 업무 도구에 그대로 옮기지 않습니다.
    WorkAdventure ↗

    영역과 사물에 실제 기능을 연결하는 사례입니다. 책장은 기억, 작업대는 제작처럼 기능의 위치가 됩니다.

    적용 한계: 방에 들어가는 연출만으로 업무 권한이 생기지는 않습니다.
    Google PAIR ↗

    여러 시스템의 우선권 혼란과 동시 알림을 실패로 봅니다. 판단 주체와 질문 창구를 명확히 둡니다.

    적용 한계: 분주한 캐릭터가 능력과 검증 수준을 과장하지 않게 합니다.
    Multi-agent Research ↗

    독립된 조사는 나누고 핵심 근거를 모읍니다. 공유 맥락과 순차 의존이 큰 일은 분업 이득을 먼저 봅니다.

    적용 한계: 특정 시스템의 속도·비용 수치를 이 작업실의 성능으로 쓰지 않습니다.
    W3C 상태 메시지 ↗

    완료·대기·오류는 글로도 알 수 있어야 합니다. 움직임을 줄여도 정보와 조작은 남습니다.

    설계 원칙: 결과를 읽기 위해 캐릭터가 걸어오기를 기다리지 않습니다.

    가장 중요한 반론은 공간이 관리와 집중 부담을 늘릴 수 있다는 점입니다. 같은 과업을 목록·정적 공간·움직이는 공간으로 보여주고 담당, 막힘, 다음 행동을 찾는 정확도와 시간을 비교합니다. 이해가 좋아지지 않으면 접을 수 있는 보조 보기로 유지합니다.
