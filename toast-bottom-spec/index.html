개발 확인 항목과 실기기 검증

어제의 6건과 코드 대조에서 나온 항목을 합쳤습니다. 답이 오면 규칙표와 문구표를 고칩니다.

개발에 묻는 것

  1. 기준 커밋 이후 최신 배포판에서 토스트 호출, 상태 처리, 화면 전환이 바뀐 부분을 확인합니다.
  2. 실행취소 후보 16건 중 서버의 실제 복구 지원 항목을 확인합니다.
  3. 복구 지원 항목별 허용 시간, 권한, 복구 가능한 데이터 범위의 확정 여부를 확인합니다.
  4. 현재 리스펙트 실행취소의 직전 상태 전체 복구 여부를 확인합니다. 복구 요청 실패 시 화면 상태 일치도 확인합니다.
  5. 노크 요청의 '기존 방' 응답이 상대의 선행 노크를 뜻하는지, 방의 존재만 보장하는지 확인합니다.
  6. 노크 응답의 방 번호가 현재 사용자가 열 수 있는 유효한 방인지 확인합니다. 모든 진입 경로에서 직접 열 수 있는지 확인합니다.
  7. 포트폴리오 등록 완료의 두 경로에서 작성창을 닫은 뒤 보이는 화면을 확인합니다. 상세 자동 이동이나 완료 안내 중복 여부를 확인합니다.
  8. 영감·프로젝트 등록 직후 상세로 자동 이동하는 진입 경로를 확인합니다. 새 버튼이 열 콘텐츠 번호를 노출 종료까지 보관할 수 있는지 확인합니다.
  9. 서버·웹 문구와 이름 등 동적 값의 최대 길이를 확인합니다. 가장 긴 실제 문구를 검증용으로 확보할 수 있는지 확인합니다.
  10. 표의 'AS-IS 아이콘 미대조'와 '(추정)' 행은 실제 호출 상태를 코드에서 확인해야 합니다. 이 답이 와야 '아이콘 추가(실패)' 건수가 확정됩니다.

실기기에서 재현할 것

  1. 등록 완료 버튼은 방금 만든 콘텐츠를 엽니다. 안내 후 목록이 바뀌어도 다른 콘텐츠를 열지 않습니다.
  2. 북마크 버튼은 콘텐츠 종류에 맞는 탭을 엽니다. 지원 버튼은 지원 목록을 엽니다. 채팅방 입장은 약속하지 않습니다.
  3. 토스트를 누르지 않고 기다려도 보기·재시도가 가능합니다.
  4. 작은 화면, 큰 글씨, 키보드, 채팅 입력창, 고정 버튼, 시트, 화면 회전에서 안내와 터치 영역은 겹치지 않습니다. 탭바 제스처 영역과도 겹치지 않습니다.
  5. 연속 저장·연속 실패·업로드 완료와 다른 오류가 동시에 나도 결과는 뒤바뀌지 않습니다. 오류도 사라지지 않습니다.
  6. 실패·부분 성공 재시도 시 이미 성공한 작업은 중복 실행하지 않습니다.
  7. 보이스오버가 읽는 중에는 남아 있습니다. 버튼에도 도달할 수 있습니다.
  8. 채팅의 ‘새 메시지 보기’와 공통 토스트는 함께 떠도 서로 가리지 않습니다.
  9. Android는 범위 밖이며 별도 검증으로 기록합니다.
