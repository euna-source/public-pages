01 · DECISION

결정 세 줄

  1. GA에 보내는 screen_name 값은 영문 snake_case 키로 확정합니다. 한국어 제목은 대장과 대시보드의 라벨 층에만 둡니다.
  2. 이미 발송 중인 이름(AOS 63개·iOS 17개)은 바꾸지 않습니다. 두 화면이 한 키를 두고 다투면 개명이 아니라 새 키를 추가합니다. 예외는 하나, AOS my_page는 my_profile_card와 같은 순간에 나가는 중복이라 멈춥니다.
  3. 화면은 "사용자가 전면에서 읽거나 입력하는 목적지"와 "독립 과업을 하는 시트"입니다. 시스템 피커·확인/완료 팝업·옵션 시트·정렬 시트·컨테이너·QA 도구는 화면이 아닙니다. 하위탭은 경로 분석에서 갈라 봐야 하면 이름으로, 같은 목록의 필터면 tab 파라미터로 나눕니다.

기각한 안과 대가

  • 한국어 제목을 GA 값으로 보내는 안(정의서 v2)은 접습니다. 발송 중인 80개 이름을 모두 바꿔 지표 역사가 끊기고, 식별자에 언어를 섞게 됩니다. 대신 GA 보고서에 영문 키가 보이므로 라벨 층의 주인이 필요합니다.
  • iOS 232행 전부에 이름을 붙이는 안은 접습니다. 화면 수가 부풀어 세션당 화면 수·체류·전환이 흐려집니다.
  • 의미가 어색한 현행명 3개(my_page_menu=설정 홈, user_resume=내 이력 관리, member_profile_inspiration=타인 프로필 인스퍼레이션 탭)는 바꾸지 않고 라벨로 바로잡습니다.

뒤집힐 조건

  • 라벨 층 주인이 정해지지 않아 GA 화면을 영문 키 그대로 읽는 사람이 다수가 되면 한국어 값을 다시 검토합니다.
  • AOS 63개 지표를 실제로 읽는 사람이 없다고 확인되면 역사 보존 논거가 사라지므로 위 3개 이름을 바로잡을 수 있습니다.
  • contacts_team(AOS)과 team_list(iOS)가 같은 화면으로 확인되면 대시보드 별칭으로 합치고, 다음 큰 개편에서 하나로 수렴합니다.
02 · NAMING RULES

이름 정의 기준

  • 형식소문자 영문·숫자·밑줄, 정규식 ^[a-z][a-z0-9_]{1,39}$. 2~4토막, 40자 이내. GA4 한도는 100자지만 보고서 가독성 때문에 40자로 둡니다.
  • 구조<영역>_<대상>[_<한정>]. 영역 어휘는 현행 발송 어휘를 따릅니다: app · signup · login · reset_password · basic_info · onboarding · home · finder · discovery · user · my · my_info · resume · media · portfolio · inspiration · project · project_card · proposal · chatty · chat_room · lounge · contacts · relation · team · setting · bookmark · notification · report · respect · knock · agreement · web · club · card_game.
  • 넣지 않는 것회원명·검색어·콘텐츠 제목·고유번호·URL·날짜, 상태(loading·error·empty), 기술 클래스명(Activity·View), UI 종류(popup·bottom_sheet. 현행 visitor_today_bottom_sheet만 예외로 유지).
  • 값의 입구대장에 있는 값만 보냅니다. AOS는 C8Screen enum, iOS는 같은 역할의 enum이 유일한 입구이며 문자열 리터럴은 받지 않습니다.
  • 불변의미가 유지되는 동안 이름을 바꾸지 않습니다. 폐기한 키는 다른 뜻으로 재사용하지 않습니다. 바꿔야 하면 새 키를 추가하고 구이름 대응표를 라벨 층에 둡니다.
  • 라벨한국어 라벨은 대장에만 있고 GA로 보내지 않습니다. <영역> · <대상> 꼴로 씁니다.
  • 발송 시점전면 표시 시 1회. 뒤로가기·탭 전환 복귀는 다시 보내고, 시트·팝업 닫힘과 백그라운드 복귀는 다시 보내지 않습니다. tab이 있는 화면은 탭이 바뀔 때 값을 바꿔 다시 보냅니다. 페이저에서 대상이 바뀌면 같은 이름을 새 screen_id로 다시 보냅니다.
  • 자동 수집Firebase 자동 화면 수집은 끕니다. iOS FirebaseAutomaticScreenReportingEnabled = NO, AOS google_analytics_automatic_screen_reporting_enabled = false. SwiftUI는 자동 수집이 되지 않으므로 수동 발송이 필수입니다.
  • 정본screen-keys.json 한 파일이 정본입니다. 대장 문서·HTML·CSV는 여기서 생성하고, 양 OS enum은 이 파일을 따릅니다. 추가·변경은 기획 리드가 승인합니다.
03 · BOUNDARY

화면인지 아닌지 가르는 순서

  1. 전면 목적지인가push·fullScreenCover·Activity·탭 루트·목록이 바뀌는 탭이면 화면입니다.
  2. 독립 과업 시트인가선택·입력을 끝내는 시트(약관 동의·필터·댓글·신고 사유)면 화면입니다. 옵션·정렬·첨부 메뉴는 아닙니다.
  3. 기존 이름으로 셀 수 있는가같은 상세의 다른 유입, 같은 목록의 필터 탭이면 새 이름이 아니라 previous_screen·tab 파라미터입니다.
  4. 갈라 봐야 답이 달라지는가경로 분석에서 따로 봐야 하는 목적지(대화방 유형·검색 결과 종류)만 이름을 나눕니다.
  5. 화면이 아니면피커·확인/완료 팝업·옵션 시트·오류 상태·컨테이너·QA 도구는 제외하고, 필요하면 행동 이벤트로 셉니다.

제외 분류와 iOS 행 수

분류왜 화면이 아닌가행
확인·안내 팝업버튼 하나로 닫히는 알림. 필요하면 이벤트(예: app_update_gate)로 셉니다.4
유도·완료 팝업행동의 결과 알림. 완료는 행동 이벤트로 이미 잡힙니다.4
시스템 피커OS가 그리는 사진·파일·메일 선택기. 앱 화면이 아닙니다.11
옵션(더보기) 시트선택지 메뉴. 고른 행동은 행동 이벤트로 셉니다.13
정렬·첨부·메뉴 시트같은 화면의 보조 조작. 화면이 바뀌지 않습니다.5
오류 상태같은 목적지의 오류 문구. 오류 이벤트로 셉니다.1
컨테이너안에 든 화면이 이름을 냅니다. 컨테이너는 이름을 내지 않습니다.1
정보 표시 시트읽기만 하는 짧은 정보. 과업이 없습니다.1
